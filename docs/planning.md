# 规划与研究

导演室、大纲、日常选材、长文消化、小说开演和研究都服务于主 Agent。它们产出讨论、提案、候选和证据，都不写正文，也都是派生物。

## 导演室

导演室是独立的创作工作台，和每拍的 director 模式无关（导演室能用不代表 director 模式能用，反之亦然）。用户原话与已提交正文优先。

- **对谈存储**：写入当前分支的 `rp-outline-chat`，按 `discussionId` 隔离，各对谈的聊天和最近方案分别进入上下文。删除、清空都是追加标记，不物理擦除，不动提案、正文或大纲。
- **完成以 `done` 为准**：回复走真流式 SSE，只有服务端保存后发出的 `done` 才算完成；断流、超时如实显示并保留输入，不自动重发。
- **生成期间拒绝写对谈**：正文生成或后台结算期间拒绝对谈写操作，否则对谈元数据会插在 user 与待保存的 assistant 之间，让正文被误判为切支。
- **上下文绑定**：写操作带会话/卡/分支指纹；关闭对谈或切支会取消流式请求，旧上下文的迟到结果不覆盖新上下文。bootstrap/reconcile 等非流式任务不保证随面板关闭而停止，应重读持久状态再决定是否重试。
- **草稿**存在当前标签页的 `sessionStorage`，按工作区、会话/卡/分支和对谈隔离；同上下文关闭重开或刷新可恢复，不自动发送；收到保存确认后只清掉已提交的那份。草稿不跨设备同步。
- **界面**：对谈、待审方案、当前大纲有直接入口，没有已确认大纲也能对谈；窄屏用"工作区"选择器导航。阅读旧记录时不强制滚到底。查看提案不等于采纳，采纳要显式确认；故事推进后过期的提案不再列为待审。

分页、续聊上限、保活与时限见 `server/outline-chat-stream.ts`。

## 大纲与提案

`rp-outline` 按当前分支祖先链读取，带 revision/hash。提案和未来节点是方向，不是已发生的事。

- **大纲模式**：`manual` 只在用户讨论时提案；`suggest` 拍后可提建议；`auto` 只自动提交审计判为低风险的更新。高风险变更任何模式下都要用户确认。
- 确认和自动提交都对基线 revision/hash 做 CAS；审计拒绝伪造来源、把计划升格为事实、删改硬约束。
- 研究开关（off/manual/auto）与大纲模式相互独立。

## 日常选材

后台空闲时为当前分支准备最多三个"剧情选项"（和卡自带的行动选项是两回事）：读当前卡、人设、最近正文、状态与已确认大纲，从日常卡库检索，交 `dailyPlot` 岗位适配。允许没有推荐。

- **默认关闭**；`dailyPlot` 必须显式配置。任务单实例、限时，和后台结算互不等待；失败不自动付费重试，手动"重新筹备"才重试。
- **推荐要有依据**：须带最新原文的短引，以及源卡活动、摩擦、微变化三段机制说明；缺失、伪造或重复的推荐不采用。资料变化后旧推荐撤下，收据保留。
- **点击只填草稿**：把文字和可取消的方向标签填进输入框，不自动发送。所有发送路径共用同一受理流程，服务端校验版本、来源与分支，方向在 user 落树 ACK 后才生效。
- **方向如何生效**：经既有候选参考通道送到导演/主作者，不增加作者、不改 3/2/2；主题持续，进入路径可变，不预定人物反应或结局。"目标已完成"只认选择之后的完整正文证据。
- **混合语义检索**单独开关，默认关。复用"嵌入连接"的云端 embedding 配置（不启用旧记忆），关键词召回与向量相似度做排名融合；建索引会产生嵌入费用，失败回退关键词。

缓存 `.liyuan/plot-options/` 只在来源与版本匹配时采用；上限见 `src/plot-options/`。

## 长文消化

"藏书消化"把文档或 Kakuyomu 作品分章分块、有界消化，产出摘要、机制资产和可复核的原文定位，供研究、导演、世界适配按需取用；原文不整部进主演上下文。

- 状态带检查点落盘，可暂停、恢复、删除；预算与最大调用数是硬上限。
- 机制只能引用引擎生成的证据索引，不接受模型自报出处。
- 网页来源目前只支持 Kakuyomu，不做通用抓取。定时发现默认关闭。
- 定时器 `stop()` 只停后续调度，已开始的那次会跑完；重复 `start()` 不叠加定时器。

入口 `src/outline/corpus.ts`、`kakuyomu.ts`、`corpus-scheduler.ts`。

## 小说开演

把已消化的作品变成可开演的故事，之后仍走同一会话树与 direct/director：

```text
Corpus 分块 → NovelSource（内容指纹、精确原文区间）
→ NovelPackage（不可变 revision）→ 开场提案（待确认）
→ 用户确认 → 内部角色卡 V2 → switchToCard() → 会话树 + StageEngine
```

- 作品包 revision 不可变；模型提取的事件引句须与源块逐字匹配，坏引句、版本漂移、路径穿越、过期提案一律拒绝。
- 开场模型只收到开演锚点允许的原文；提案要用户确认，确认后经现有切卡事务开新分支。
- 开演后的原著节点只是候选，经导演路径参考，当前分支事实优先。`rp-novel-play` 只存作品版本、进度和冲突元数据；重 Roll 不重复推进进度。
- 提示词在 `skills/小说*`，TypeScript 只做编排、解析和校验。
- 作品包升级后优先读新版本的进度，新版本没有记录时才继承父版本。人物画像世界书按卡与作品版本分别保存，挂为该卡的附加书；历史上已挂到全局的不会自动移除，需在世界书绑定界面手动核对。

## 研究

研究是主 Agent 按需调用的只读工具，不是每拍必经步骤。工具：`web_research` 找候选、`web_open` 读原文、`canon_research`/`corpus_research` 查开演作品和绑定文档、`research_record` 记结论与缺口。director 下已读证据进入专家的 `sources`。

- 只有 `web_open` 实际读过的原文才是证据，搜索摘要不能冒充。研究结论不自动写入世界书、记忆或会话树；网页内容是不可信数据，不是指令。
- **外发授权**沿用 `webResearchMode`（默认 `off`；`manual` 需用户明确要求；`auto` 由作者决定）。`webResearchPublicTerms` 只放用户批准的公开标识；外发前本地检查角色身份、私人原话、原稿与凭据。
- 研究缓存按会话、卡、资料、授权、作品版本与祖先来源隔离。
- **研究网络**独立于模型网络：默认沿用环境代理，代理失败不改直连；可在私有 `.liyuan-research/network.json` 写 `{"version":1,"route":"direct"|"environment"}`。网页读取保留 TLS、IP pinning、内网拒绝与大小上限。
- `src/research/agentic-loop.ts` 是行为契约与测试 oracle，不是生产调度器，不要往上接模型。
