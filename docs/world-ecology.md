# 账本、世界与生态

正文之外的状态分三层，各管一摊，不互相复制：

| 工件 | 管什么 | 开关 |
| --- | --- | --- |
| `rp-state`（场记账本） | 镜头内：当前时间、在场角色、名册 | 随后台结算运行 |
| `rp-world-manifest` / `rp-world-state` | 制度、历法、组织、地点环境等持续系统 | 世界推演，默认关 |
| `rp-ecology-state` | 镜头外：人物生活、场所、事件、通讯、认知与传播 | 鲜活生态，默认关 |

三层都是派生物，随会话树分支、回档、重 Roll（见 [architecture](architecture.md#数据事实与派生)）；都在后台结算里运行，不写正文、不替用户行动。界面上的日历、舆情、认知是只读投影。

两条贯穿三层的原则：

- **后台全知不等于角色知情**。幕后生成的信息不能经导演报告或调试界面泄露给角色；读者知道不等于用户角色知道，"公开"也不等于某个角色已经听说。
- **用户的行动只来自用户**。用户角色的行动与承诺只能来自真实输入或已存正文。

## 场记账本

场记（`scribe` 岗位）在每拍正文保存后提取镜头内状态写进 `rp-state`，同时产出世界推演要用的事实信封。下一拍装配时账本只作参考，正文优先。

- 拍后结算失败按通用规则留 pending。被供应商明确拒绝的不会被下一条输入自动重发。
- 手动入口：`POST /api/state/retry-ledger` 只请求一次显式配置的 `scribe`，不跑其它领域；`POST /api/state/confirm-ledger` 不调模型，带来源与版本 CAS，追加一份用户确认的快照。

代码：`src/stage/ledger-status.ts`、`scribe-run.ts`、`src/scribe.ts`。

## 世界推演

三层结构：

- **卡级画像与 Manifest**：根据卡和资料选出适用模块、类型、初始规则，存在卡级私有目录（`src/stage/literary-world-profile.ts`）。
- **分支世界状态**：`rp-world-manifest` 记录当前祖先链用的画像版本，`rp-world-state` 存已确认状态。
- **模块 Skill**：`skills/世界推演`、`世界模块-*`、`拍后事实信封`、`世界转移审计`。提示词都在 Skill 里，TypeScript 不写文学提示词。

每拍转移：已存正文 → 事实信封 → 到期模块提案 → 审计 → 按固定顺序提交。

- **事实信封**只提供镜头内参考，不限制幕后创作。提取失败记 `fact-failed`，世界领域留 pending 等恢复，不用空信封冒充成功；成功提取但没有事实是合法结果。
- **幕后发展**可以依据设定和模块状态生成，标 `provenance.kind=generated-offscreen` 并绑定本拍来源，不要求正文引文。
- **审计**：提案要过设定、因果、时间、用户主权与知情审计才采纳；失败保留旧世界和审计收据，不报推演成功。
- **画像**：没有画像时先交付正文，再由世界领域建画像并结算本拍；只保存完整可解析的画像，不伪造默认画像。旧画像只经同卡的祖先 Manifest 找回，不跨卡、不跨兄弟分支扫描。周期复核是空闲时的后台任务；手动分析可在推演关闭时运行，但不顺带打开推演。
- **重 Roll** 可沿用同卡已有画像版本；Manifest 在新 assistant 保存后才落树。
- **画像输入预算**：世界书投影最多 40 条、每条 2,000 字符、总计 24,000 字符，保留实际送达条目的来源 id；只影响画像分析，不改原件。恢复时本拍正文单独放在 `latest_turn`，不重复传入历史。

## 鲜活生态

三层：全局叙事原型池（可复用的生活/场所/事件机制）→ 卡级生态池（按卡和作品资料生成的适配模板）→ 分支运行态 `rp-ecology-state`。两个池在 `.liyuan/ecology/`，是备料，不是事实。

- **备料不阻塞正文**：direct 只读已有池和生态投影，不在拍前新生成；director 的生态专家读同一份资料。后台搜索与备料为后续拍服务，单条运行链，写前重读最新池再合并。
- **拍后 aftermath** 可按世界时间、人物状态和因果生成场外事件、关系与观察。`origin: generated-offscreen` 不需要在正文出现；`origin: narrative` 必须带与已存正文匹配的引文（来源 id + 逐字引文）。会话/卡/revision 只用于提交与恢复，不能当叙事证据。
- **秘密**的获知与传播必须有实际渠道和获知过程。
- **统一采纳**：所有候选（含众生侧写）经统一校验和采纳才进入生态状态。JSON 可解析但来源或引文校验失败，做一次同岗位结构修复，修复后仍完整校验，失败整批不采纳。
- 世界与生态可以并行计算，但按既定顺序串行落树；取消或切支拒收迟到结果。

## 世界与生态的分工

世界管制度和环境；具体人物生活和事件归生态单链。两边只通过跨域信号互读（`src/stage/literary-world-signals.ts`），同一件事不双重推进。信号是派生参考，和事实信封分开。

- **世界 → 生态**：排除秘密记录，保留公开/可发现记录和日历约束，按原顺序最多 30 条。
- **生态 → 世界**：按原顺序最多 20 条。进行中/预定的非秘密事件可供参考；有公开传播面时只用公开版本（保留说法性质、来源类型、受众、范围、结果），只有痕迹时只用痕迹，不附内部事件名、地点或幕后进展。私有传播面、无公开面的秘密事件不投送。已结束事项只投送公开的结果或痕迹，标为终态后果，不重新推进。

## 众生侧写

梨园内置模块（不是上游插件）：每拍正文定稿后，为镜头外的几位人物写"同一时间他们在做什么"，作为候选交给鲜活生态。它只是生态内部的候选来源，不是第二个推进人物的引擎；采纳后的生态状态和 `rp-npc-parallel` 收据才是落点，原始侧写不直接给作者、MVU、数据库或记忆。早期的原 NPC Parallel 插件已移除，原有的会话设置、忽略名单与已采纳侧写按原路径继续读取。

- **运行条件**：模块开关（全局，默认关）、鲜活生态、`stepModels.npcParallel` 三者都满足；会话设置里可单独停用。
- **选人**：名单来自已提交的生态人物和账本名册，排除主角、卡名和忽略名单。正文里提到最多的名册人物每拍必写一位（本拍没有则回看更早的正文），其余按权重无放回抽样，最近写过的人降权（冷却为零时不降）。返回的名字按规范化后唯一精确匹配绑定，有歧义就不绑。人数、冷却、字数、人称、写作要求、忽略名单按会话/卡保存。
- **请求次数**：侧写生成每拍最多 1 次请求，一批写完所有选中人物；没有合格目标就跳过。同来源同材料的成功批次直接复用。候选接入生态及必要的一次结构修复另算请求。
- **结果**：一批候选是 accepted / rejected / empty / failed 之一。没写出来的人本拍跳过，一个都没解析出才算失败。空报告、错人物或虚构主角承诺修复一次，仍失败留 pending；失败批次可"复用已有侧写，仅补采纳"，不重新生成（`POST /api/turn/retry-npc-admission`）。候选绑定来源、模块版本、稳定人物 id 和文本 hash，重名不合并。
- **设置写入**按来源 + revision 做 CAS，生成或后台整理时拒绝修改，不接受已变成祖先的旧来源。设置面板的离开保护见 [plugins](plugins.md#插件中心)。

## 后续写作怎么用

`formatLiteraryEcologyInjection` 把已采纳的生态转成只读参考，供主作者、文学导演和 director 生态专家使用。世界与生态各自按开关投送，模块关闭时不发送其保留快照。

- 默认 6,000 字符预算内交错选取完整记录：进行中的公开事件、社会传播面、已结束事项的后果、人物此刻活动、场所运行、可发现线索；优先最近推进项。预算放不下就不投送，不从中间截断。
- 已结束事项只供后果参考，不重新打开。有公开传播面时用公开版本；私有传播面不进入投影。不发送可能混入幕后真相的自由摘要，不暴露人物的私有目标或认知账本。
- 参考不回写状态，也不能覆盖当前正文。投影目前按类别与近况平衡，还不按当前场景参与者排序。

ST-SevenDaysCal（历法、时间跳转）和 world-backstage（冻结认知、通讯送达、公开传播面、事件终态）提供了产品思路，梨园在上述边界内独立实现（见 [materials 来源与署名](materials.md#来源与署名)）。
