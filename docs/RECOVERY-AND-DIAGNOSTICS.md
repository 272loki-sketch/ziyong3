# 当前投递、恢复与诊断

## 提交与分支

Web普通剧情绑定mode/session/card/clientMessageId。忙时输入只排队；处理新拍前先对适用pending做来源/分支守卫与恢复，成功后才落user、flush并发送accepted ACK。恢复失败时服务端拒绝本条、不向 Session Tree 落user，客户端保留输入草稿。ACK只表示输入已保存，不是整拍或模型恰一次成功。deliveryProtocol支持的自动重放进入同一受理入口并沿用消息ID；旧SDK没有可靠ACK保证。

叶守卫容忍真正的设置元数据，不容忍切会话/切分支。取消丢弃迟到结果；已保存正文可留下pending领域收据。自动新拍前置与显式手动恢复共用数据库来源守卫helper，但恢复失败不让新的剧情输入先落树或获得ACK；不能为恢复重写故事或重复已经提交的世界/生态/账本。

重Roll失败只有没有新回复落树时才回退；已有新稿/半稿即使返回拍后error也保留。历史格式pending只重挂作者原稿，不请求模型补格式；漏接同卡世界画像须核对同源运行记录后补缺失世界结算，不能重跑已完成生态/记忆。

## 正文就绪与后台整理

作者原稿／格式已保存并绑定交付后即上屏，后台结算不再延迟正文展示。`hello.settling`与`agent: settling`让刷新／断线后继续显示已交付正文，不恢复生成壳。输入可排队；导航、编辑和重Roll仍遵守共享写锁。停止后台不会把已完成作者标为半稿，数据库/插件/领域pending先持久化，下一拍恢复。后台请求取消／来源变化不得补记complete或把迟到结果写入新分支。

## 观测

工作流状态、正文首字、正文＋格式就绪耗时（`timeToAuthorReadyMs`）、含后台结算的完整耗时、实际调用和用量分别记录；并行阶段不能相加当总耗时，供应商内部重试/隐藏用量未知。失败/降级不显示成功，校验失败不是另一笔HTTP调用。

原生tools不支持、错误schema/参数、伪工具文本、认证、网络/524、专家报告来源校验、历史格式交付失败和真实作者截断是不同问题；不能用降级工具或换模型掩盖。

## 实战记录

只读全屏阅读、目录按需展开，窄屏不横向溢出；原始正文/格式可核对。记录读取不切生产会话。旧生图系统已退役，插图仅只读展示已有图片及折叠的“历史图片提示”，无生成或配置操作；源码与部署状态分列，见 [退役边界](IMAGE-GENERATION-RETIREMENT.md)。

## 限制

未做原子“多供应商恰一次调用”，也不把文学质量等同协议通过。流式首包超时修复见 `MODEL-CONNECTIONS.md`，记忆实际写入/召回见 `PLAN-RP-MEMORY.md`。完整thinking只能在私有记录中按timestamp核对，方法见 `READING-THINKING.md`。

## 逐次真实请求

提示词查看器捕获最终API载荷与供应商/SDK回执，原预览不冒称实发；缺失用量、未捕获旧请求和重启中断分别说明。本拍逐次请求可用id核对，原并发/供应商内部重试限制不取消，详见 `REQUEST-INSPECTOR.md`。


## NPC来源校验恢复

原NPC短在场判定输出也消耗推理预算；截断仍失败，不借用主作者。生态报告无真实用户／已保存正文承诺锚点是技术校验失败，应同岗位收费修复一次，不能拿旧生态快照把本拍记成complete。仍失败则pending，下一输入仍先恢复。

旧精确假完成收据自动视为待恢复，读取该正文前生态；失败再试也不能因旧来源快照存在而跳过计算。成功只纠正同拍，已完成账本/世界/原交付不重复推进；真实业务 reject 仍保留。候选、额度和独立岗位合同见 [NPC-PARALLEL](NPC-PARALLEL.md)。

## 诊断顺序

1. 用真实 session/card、输入 ID、正文 entryId 和祖先链定位，不按文件 mtime 猜最新；仅需状态时不展开私人原文。
2. 分清输入 ACK、作者完成和后台完成：`onAuthorReady` 表示完整原稿/绑定交付已保存，`onTurnEnd` / `performTurn` 结束才包含后台；`settling` 不表示作者仍在写。
3. 查每个领域收据的 complete/pending/failed/skipped，核对 source 与 revision。不要仅凭旧状态存在认定本拍完成，不把缺工件当零调用。
4. 断流、超时或关闭面板后先重读持久状态及实际请求。界面等待结束不保证服务端撤回，盲重试可能重复收费；系统没有跨供应商原子恰一次调用保证。
5. 恢复只补合法来源的缺失领域。MVU 可单独恢复当前完整交付，显示润色失败继续显示原稿；对应限制见 [MVU](MVU.md)、[VERIDIS-REWRITE](VERIDIS-REWRITE.md)。

## 源码与验证

`src/stage/engine.ts` 管理排队、作者交付、共享写锁与领域恢复；`server/main.ts`、`server/wire.ts` 和 `server/rest.ts` 提供投递、WS 状态和管理操作。`src/stage/request-journal.ts` / `server/request-inspector.ts` 记录实发请求，`src/stage/performance.ts` 管理耗时投影。领域恢复另见各插件指南。

测试命令见 [TESTING](../TESTING.md)。合成断线/取消/分支回归不证明所有供应商的计费、内部重试或长局文学质量。公开问题报告只提供脱敏错误类别、时间和状态；私人原稿、thinking、Key、完整请求和截图不进入公开提交。
