# 梨园版本同步、分支与隐私规约

同步的目标是把经过审阅的产品变更引入正确分支，保留本机增强和私人资料。同步不等于升级运行中的服务，不授权 commit/push/Release，也不授权清理历史或更改用户配置。分支发布合同以 [BRANCH-RELEASE-WORKFLOW](BRANCH-RELEASE-WORKFLOW.md)为准。

## 1. 分支职责

`main` 保存当前已验收公开产品，`local` 用于本机增强与部署同步，`release/vX.Y.Z` 保留版本节点。分支名不证明某台服务实际运行了对应版本。原项目更新通过显式上游 remote 或 review 分支审阅，不把本 fork 的 `main` 当作原上游基线。

## 2. 同步边界

1. 先读 AGENTS、现行架构、两模式与执行合同；记录当前分支/跟踪关系与 dirty 状态，辨认本机增强。只读同步请求不改代码。
2. 获准后 fetch 指定 remote，核对头、祖先、提交范围与 diff，不自动接受未知冲突或运行上游安装脚本。
3. 特别审阅作者流程、Skill/预设职责、事实来源、工具权限、插件宿主、SDK 与静态资源变更；不能重新引入旧 ask、心理画像、稿纸或拍后格式模型流程。
4. 在隔离候选中处理依赖和构建，运行隐私候选审计、`verify` 与必要专项。不能用旧仓库配置子集覆盖真实连接、默认模型、岗位或未知字段。
5. 普通快进优先，分歧在授权的 review/merge 流程协调。冲突停止并报告，不 reset、不 force-push，不擅自 stash 或丢弃继承改动。
6. 若获准提交，精确暂存后检查 `git diff --cached` 与 `npm run privacy:staged`。若获准推送，核对所有新增提交和远端头，推送后独立验证。
7. 按用户授权，维护/部署默认不新建手工本地备份或归档；先核验 GitHub 恢复仓库、精确 commit 与匹配产物来源、校验和及可获取性。部署仍须另行授权，完成隔离候选验证、空闲检查、候选切换、health/hello/bundle/SW 和私有数据保护核验。

`npm run privacy:check` 检查工作树公开候选，`privacy:staged` 检查实际暂存字节；工具入口未接线或失败不能算门禁完成。范围与局限见 [PROJECT-STRUCTURE](PROJECT-STRUCTURE.md#隐私检查)。

### 现有脚本限制

`scripts/update-local.sh` 是有副作用的便利脚本，**不是上述流程的只读实现**。它要求 `local` 与 clean 工作树，备份后 fetch/merge，使用 `npm install`，直接构建 `web/dist`；检测到对应 systemd 服务时会重启。它的备份列表不是所有现代插件/媒体/研究路径的完整清单，也没有完整候选构建、隐私门禁和部署保护验证。

该旧脚本仍会新建本地备份/归档，**不符合新的默认不新增手工归档流程**；文档没有改变其行为。不要在继承 dirty、只读任务、未获部署授权或未明确批准归档例外时运行它，不要为满足 clean 检查自动提交/stash 私人资料。确需使用须另行授权其归档、重启和依赖写入等副作用，先审阅脚本并补齐恢复源核验与必要门禁；默认按分离的人工审阅与部署流程操作。

`scripts/apply-update.mjs` 也仍会保存旧代码到 `.liyuan-cache/backup-<旧版本>/` 并用于失败回退，这是更新器内部恢复机制，不因停止手工维护备份而禁用，也不应宣称旧更新入口已实现无归档流程。本文不修改或运行脚本，不删除已有备份，也不改变更新器既有管理行为；自动原子写入 `.bak` 同样保留。

## 3. 私人资料不进入Git

API/OAuth/SSH/临时凭证、真实运行配置、会话/正文/thinking、用户卡/预设/人设/世界书、私人 Skill、媒体、截图、记忆、插件原缓存与备份保留原处。`.liyuan/extensions/` 是产品源码例外；`skills/` 是内置协议，`.liyuan-stage-skills/` 是私人覆盖。

目录与真实路径类别见 [PROJECT-STRUCTURE](PROJECT-STRUCTURE.md#现有私有路径)。`.local/` 只可作为未来运维输出约定，不能把文档建议当成已有运行时迁移。GitHub 只覆盖已推送、核验且获准公开的内容，不覆盖未推送提交、dirty、实际用户级 Agent 目录、项目私有路径、容器数据和插件存储。上述资料留在原处，不通过遍历私有原文或放宽权限来方便验证；操作若危及未覆盖内容，停止并请求专项保留/恢复方案，不自动备份、提交或推送，不回滚故事/数据库来回退代码。

模型工具能力按模型保存、默认支持；升级保留当前启用渠道、默认模型和其它兼容字段。Gemini 3.7/3.8 Flash 不整体换成 Luna，仅 Luna 自身旧名迁移到原生 `gpt-6-luna`；独立岗位/嵌入配置不能合并。生产 PNG 不拿来试写，原记忆不删除、不为测试重生成。

临时认证不写 URL、Git 配置、脚本或日志。公开示例使用占位地址、合成材料；原插件再分发和素材许可不能由项目许可证替代。

## 4. 历史记录

历史一次性清理、误开 PR 或旧部署修复只用于溯源，不构成未来权限。保持普通提交/快进与版本节点，失败保留现场。报告分别列源码、远端、服务和 Release 的实际状态、完成命令及未完成门禁；后来的成功不覆盖先前失败或未知 usage。
