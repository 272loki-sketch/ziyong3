# 当前卡格式：原作者一次交付、原正则展示

适用于 Web 的 direct/director。正文与卡格式由同一个作者一次交付，展示投影不成为第二份故事。

## 当前流程

```text
启用的原始预设 / 角色卡 / 世界书 / 本拍输入
→ 同一个正文 Agent 写正文与卡格式（保留其已有多阶段思考/工具流程）
→ 原作者交付原样保存
→ 绑定的原始显示正则 → HTML/CSS 或文字展示
```

**不再拍后调用模型识别格式需求、生成布局或补齐格式；不检查卡格式作为成功门槛。** 不强制图片、行动选项、固定面板标签、引用布局 JSON 或 `sourceReviews`。原资料中的格式指令仍交给作者理解，未知标签、HTML、Markdown、JSON及其位置不由系统名单替代；关闭素材不因其正则仍存在而重新启用。

作者截断、API `length`、真实断流、工具协议失败与领域结算失败仍如实诊断。取消格式门槛只消除额外格式调用/二次收口造成的失败，**不能保证 API 本身永不截断，不能保证模型必然遵守全部指令或完成全部剧情**。

## 数据分工

| 工件 | 用途 |
| --- | --- |
| `details.rpAuthorDraft` | 主作者完整原交付，刷新、恢复和正则预览的显示源；不改写原稿 |
| `details.rpNarrative` | 供账本/世界/生态/记忆使用的故事事实投影；不替代完整显示稿 |
| `rp-presentation-delivery`，`origin: author` | 绑定 `targetEntryId` 的原稿展示引用；`display` 使用原交付，`body` 是既有事实投影，`requirements` 为空 |
| `rp-turn-settlement.presentationDone` | 原稿展示投影是否已保存，不代表“格式已检查” |
| Wire `authorDelivery` | 当前授权会话的未改写原作者文本，用于只读预览；不包含另外的模型思考或来源提示词 |

显示继续经过原作者正则和已有安全策略（思考折叠、HTML沙箱等），不是把原始标签直接插进主页面。规范事实抽取不再请求作者另交“正文边界 JSON”；拆开已知正文容器时保留容器后续叙述，不在第一个 `</content>` 处切掉后段。无法识别的自定义结构也不成为格式门禁，不触发第二次模型调用。

新两模式在原稿与 `rp-presentation-delivery` 已flush后立即交付给前台，不再等场记、世界／鲜活世界或数据库填表。后台期间正文/格式已经可以完整阅读，作者结束与领域完成是两个独立状态；MVU等派生快照尚未就绪时仍按原来源重查，不捏造已更新变量；后台完成的同源只读刷新通知让卷宗及时显示已保存快照，不重跑卡脚本或插件结算。

新稿已经保存时，任何拍后错误都不能让重Roll悄悄切回旧稿。API真的只交半稿仍标明未完成，保留原文，不凭展示原稿把半稿宣布成定稿。

## 可见正则界面

主界面管理入口 **“正则与渲染”**：

- 原始规则与实际 `cardfront` 共用绑定清单，顺序为预设 → 挂载世界书 → 角色卡。卡内世界书自动随卡读取，不额外复制成挂载书。
- 查看来源文件、当前预设草稿、规则顺序、关闭状态、显示/送模用途、深度条件、匹配表达式、原始替换串和跳过原因。
- 可载入当前显示轮原稿或粘贴合成文本，按全部显示规则或单规则做本地预览；可调整消息深度、临时不套正则，查看替换后全文和应用记录。
- 只读、不修改卡/预设/世界书/正文/记忆、不调用模型。暂不支持的原字段会明确显示，不假装执行。
- 正则在可终止 Worker 中预览，超过 2 秒或展示展开过大就停止该次预览，不冻结主页面；这是预览保护，不是生成格式门槛。
- HTML预览为静态沙箱，不执行卡脚本、不加载外部资源、不生成图片，不触发插件副作用。真正交互脚本仍由正常聊天的原宿主处理，不能把静态预览通过当所有脚本已验收。

## 历史兼容与恢复

旧 `rp-presentation-delivery` 和 JSON解析器保留读取兼容，但不再用于新两模式的格式生成门禁。兼容解析器修正了中文标签名的连字符范围和 `\b` 的中文边界错误。

旧格式 pending 恢复只重新挂载已存作者原稿，无格式模型请求，不重写故事、不重复已完成账本/世界/生态/数据库/插件。原来因漏接世界画像而误记 `worldDone` 的分支会单独核对同源世界审计；必要时只补缺失的世界结算，不能拿重新展示原稿冒充世界已经运行。

“重载原交付”只重新挂载已有原稿，不再意味重Roll格式。没有显式新模式的旧SDK稿纸/谢幕路径暂保留原兼容行为，不作为新Web流程。

入口：`src/stage/engine.ts`、`agent-presentation.ts`、`server/main.ts`、`server/wire.ts`、`server/rest.ts`、`src/regex-inspector.ts`、`src/regex-preview.ts`、`web/src/components/RegexManager.tsx`。历史 `卡格式需求识别` / `卡格式完整交付` / `主作者正文边界` Skill 不再由新两模式自动执行，用户私人覆盖不被删除或替换。


## 检查说明与心声作用域

完整生成检查块是独立的匹配范围；其中写出的字面 inner/content 示例不能跨入正文，心声只匹配真实心声。仍由原卡规则处理原检查折叠面板，无 renderer 则进思维折叠；不在正文显示裸审查声明。对白与心声等嵌套 HTML 保护片段从父到子还原，内部占位符不成为可见文字。不能靠删除占位符掩盖正文丢失；原作者交付、规范正文和预设要求不改，不新增收费格式模型。


### 检查示例必须是文字

`rule_check` 只接受自己的整块原规则，不能继续触发对白/心声的内联美化；捕获文字转义后交给原检查面板，inner/content 示例不变成 DOM 标签或嵌套 HTML。普通正文和 BBS 的后续规则不受此例外影响。

## 诊断与验证

1. 先比对完整 `rpAuthorDraft`、事实投影和绑定 `targetEntryId`，区分原作者缺内容与展示丢内容；不要以短事实投影代替原稿。
2. 在“正则与渲染”中查看实际规则来源、顺序和跳过原因，再用合成文本或授权的原稿只读预览定位。
3. 检查面板必须实际展开和收起，核对完整文本、字面标签、围栏/源码尾巴及桌面和手机 DOM。折叠不漏、无 page error 都不足以证明正确。
4. 行动选项在作者正则优先后的显示策略层保留严格 `<options>` 范围，到 React 才转换为按钮；未知标签处理不能先把它解成裸选项再叠按钮。显示转换不回写原稿、正文、上下文或旧存档。
5. 后台变量未更新时核对领域收据，不请求模型补作者格式。Veridis 的可选 source/原稿 hash 绑定投影也不回流事实或变量，失败仍显示原稿，见 [VERIDIS-REWRITE](VERIDIS-REWRITE.md)。

显示实现还包括 `web/src/components/Messages.tsx`；测试入口见 [TESTING](../TESTING.md)。静态预览、格式结构检查和合成回归均不证明所有卡脚本可用或文学质量合格。
