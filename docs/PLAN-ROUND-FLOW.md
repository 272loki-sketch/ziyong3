# 当前正文生成与结算流程

本文件是正文引擎的执行契约：规定作者、事实保存、前台交付、后台结算和恢复的职责。它不是部署日记，不证明任一服务版本、公开 Release 或测试通过数。模式使用见 [GENERATION-MODES](GENERATION-MODES.md)，模块责任见 [ARCHITECTURE-OVERVIEW](ARCHITECTURE-OVERVIEW.md)，验证方法见 [TESTING](../TESTING.md)。

## 一拍的共同骨架

1. Web正文输入绑定 `generationMode`、session、当前卡和客户端消息id；引擎忙时只排队，尚未写入 Session Tree 或收到服务端 accepted ACK。
2. 每条direct/director Web输入开始处理时，先对适用的上一拍pending执行来源/分支守卫与必要恢复，再持久化新user并发送accepted ACK；恢复失败则本条不受理，新user不写入 Session Tree，服务端返回 rejected，客户端草稿保留。新拍自动前置与显式手动恢复共用数据库恢复helper。ACK仅表示输入已保存，不表示整拍完成；deliveryProtocol的自动重放进入同一受理入口，旧SDK无可靠ACK保证。
3. ACK后按当前分支和已持久化输入组装作者上下文，再执行绑定模式。
4. 正文只有同一个主Agent可写，专家、工具回执和生态候选不写故事。
5. 以 `rpNarrative` 保存故事事实；`rpAuthorDraft`保留原交付，完整显示稿由绑定正文id的 `rp-presentation-delivery` 引用；事实投影不替换显示原稿。
6. 原稿与绑定交付 flush、pending收据保存后，立即发出 `onAuthorReady`，前台以完整原稿／原正则展示正文与格式；这就是正文生成的完成点，不等待任何拍后模型或数据库填表。
7. 场记、启用的世界／鲜活世界、记忆、插件派生状态以及用户授权的Veridis显示润色异步续跑；界面显示“正文已就绪 · 后台整理”，不再占用生成气泡或发送按钮。
8. 后台必要结算完成或明确pending后释放共享分支写锁；期间新输入可发送但只排队、不落树/ACK，出队后仍须通过必要恢复，不能让下一位作者读取过期账本／记忆。取消、切支、切会话拒绝迟到结果；已交付正文不被撤回、旁路重写或改成半稿。

## 直出 direct

原始启用资料＋当前分支＋已有记忆/世界/生态 → 正常文学导演（`literaryDirector`，原职责与Skill保留）→ 单主Agent普通文本 → 原作者正文＋格式立即交付 → 后台共用结算。

不额外生成拍前生态，不跑心理画像、多角度团队审稿。直出不是“一次API调用”，启用领域仍有自己的调用，正文与卡格式则由同作者一并交付；没有拍后格式识别/生成模型或格式门槛。

## 导演 director

主Agent主持固定顺序：

```text
evidence：连续性、设定/知情、生活生态三份报告
→ ideas：两个独立角度
→ writing：主Agent起草
→ review：事实、原始预设两份审阅
→ decision：主Agent选择保留或修改
→ revision（如需）：仍由主Agent改稿
→ finalize → 原作者交付保存／原正则立即展示
→ 后台共用结算（与前台交付分开）
```

日常和关键回合同流程；报告可没有意见，不要求制造冲突或强制改稿。专家不互相读取同阶段报告、不接收完整主Agent思考，没有正文/定稿工具。失败报告不能显示“审阅通过”。

## 权限、格式与事实

- 新Web不使用 `ask`剧情停点、Sogon/Sigon自动画像或逐段`draft_append`门禁。旧SDK稿纸实现仍存在于代码，但不是第三种Web模式。
- 原始预设决定写法；角色卡/启用世界书决定格式需求。系统负责执行协议，不擅自删预设、加通用文风规则或冻结主角行为。
- 未提交草稿、候选、报告、图片提示词、布局与工具回执不是已发生事实。世界/生态提交需要本拍输入或已保存正文的来源锚点。
- 原稿显示恢复绑定原正文id，零格式模型调用，不重复世界、生态、账本或故事。原资料和API自身负责作者格式，程序不为原交付设置格式验收门槛或强制补交；可选显示投影的结构/来源保护另列。已保存重Roll的新回复不能因结算报错回退旧版。
- 用户明确授权的原Veridis只生成source/原稿hash绑定的独立显示润色投影；原稿与事实原样保留，原选项/变量/HTML等格式不能被带改。投影不回流作者事实、场记、世界/生态、MVU、数据库或记忆；显示候选的结构保护不是原作者交付格式门槛，零格式生成/补齐合同不因此改变。
- 文学质量不等同于“流程状态全部成功”；结构保持也不证明100%文意或人设不变。

## 前台交付与后台完成

`onAuthorReady`只在作者真实完成、正文和原格式都已持久化后触发；direct收到完整作者终态，director仍须完成既定review/decision/finalize，不把中间草稿冒称定稿。`onTurnEnd`和引擎`performTurn` Promise仍表示包含后台结算的完整运行结束，用于共用锁、排队、恢复与旧SDK兼容；不会为了提前上屏盲目fire-and-forget共享Session Tree写入。

WS的`hello.settling`及`agent: settling`区分后台阶段；刷新／重连回读已保存完整原稿，有source/原稿hash匹配的完成润色投影时可恢复对应显示，不改原稿、不复活“正在写正文”壳。后台中导航、重Roll、编辑及插件设置的原busy保护保留，普通输入恢复发送并排队。停止后台只保留未完成收据，下一拍恢复缺失领域；格式不重新生成，已完成领域不重复提交。

后台调度合同：以同一份已保存、冻结的规范正文及拍前快照，并发运行场记、世界、鲜活世界、原数据库填表、酒馆插件（含MVU）、Veridis显示润色六路计算，并以`allSettled`收集结果；数据库和酒馆插件/MVU不等待场记、世界、生态或style结果，彼此也不作为默认前置依赖。Veridis只读完整冻结原稿与绑定规范正文，不为其余领域生产事实输入。原NPC候选生成/统一采纳放在鲜活世界路内部，不新增第七路或再次并行推进同一批人物。世界事实提取→提案→审计仍保留内部真实依赖顺序。世界各阶段显式使用 `rpStateBasis: 'pre-turn'`，生态使用 `stateBasis: 'pre-turn'`：拍前账本只投送为 reference-only，不冒称本拍最终账本；事实提取和生态可信正文完整提供、不截断，冻结规范正文中的本拍事实优先。旧SDK等未指定 basis 的调用继续使用串行结算后的既有账本合同，不据此恢复旧正文流程。

作者有待执行的资料/面板写操作时保留 owner 写入例外：依赖这些资料的数据库和酒馆插件/MVU在 owner 操作完成后再运行，避免读取修改前的资料；这不让世界/生态等待场记。六路计算不并发写共享Session Tree；任务退出后按取消、session/card/分支、来源与revision/CAS守卫检查，再串行提交各领域状态、收据和树快照，插件私有派生写入同样保留自身守卫。共享锁不提前释放，失败或取消的缺失领域留pending，下一拍按正文id及完成收据恢复，不重写正文、不重复已完成领域、不推进过期结果。

`timeToAuthorReadyMs`记录正文＋格式就绪耗时，`totalMs`仍包含后台。原插件/MVU等派生面板可能稍后更新，不能把作者原格式视为后台变量已经结算；按来源只读重查负责后续显示；后台结束的权威hello触发绑定entryId／entryScope的`liyuan:turn-state-refreshed`，只读卷宗立即重查，不依赖有界轮询一直持续，也不重载原插件realm／重跑卡脚本。

## 预算与模型

默认整拍 direct 30分钟、director 60分钟，可由配置覆盖；普通作者最多8/24轮，单流硬上限15分钟。触限保留未完成收据，不自动冒称定稿；专家按固定岗位并行，岗位失败与不支持工具分别处理。

模型按各岗位配置解析，不把所有岗位换成同一个模型。Gemini 3.7/3.8 Flash和Luna独立管理，保存时保留完整启用配置中的渠道、默认模型、其它岗位和未知兼容字段。`npcParallel/veridisRewrite` 使用各自独立受管岗位，实际选择由用户配置，缺配置/不可用不fallback主演或通用恢复；每session/card/source各8次独立持久受管额度，NPC包括原生成/生态接入/schema修复，失败尝试计数保留。温度经受管通道传递，实际usage与尝试数分别记录；缺usage不记零账单。详见 [模型连接](MODEL-CONNECTIONS.md)。

## 记忆边界

原插件启用时，拍前执行原生拦截器、召回任务与原模板输入写回，按原世界书字段投送，拍后只以已保存正文id执行原插件填表/持久化；失败留下 `rp-database-memory:pending`，下一拍先恢复，不重复正文。旧周期入库、事件提取和旧压缩关闭，原库保留；插件关闭时沿用旧路径。记忆不覆盖分支正文或账本，详见 `DATABASE-PLUGIN.md`。

代码入口：`src/stage/engine.ts`、`agent-turn.ts`、`agent-director.ts`、`agent-presentation.ts`。验证：`test/generation-mode-engine.test.ts`、`generation-format-parity.test.ts`、`memory-narrative-window.test.ts`。

## 共同原酒馆插件边界（v1.8.13）

标题保留供已有链接定位；执行边界不局限于该版本。来源安装、启用和自动更新是独立状态，不能由文档或测试隐式开启。

发送前原模板/助手事件，正文保存后只整理派生扩展；辅助候选不替换作者或写正文。每session/card/source8次单独持久化，不等同作者8/24轮，回合nonce/入口signal/scope/source拒绝取消及换代。主界面“酒馆插件”提供独立原管理台；已开聊不能由卡开场脚本重写故事，见 `TAVERN-PLUGINS.md`。


## NPC生态采纳与显示润色收据

- `rp-npc-parallel`绑定正文来源、人物id、上游commit和候选hash；NPC原始侧写不是正文事实，须经单条生态链完整采纳。明确业务拒绝或缺真实来源的用户承诺会整批隔离拟议状态，不用另一个生态故事来补成功；原稿不追加/改写。pending恢复复用对应来源候选及完成收据，不重写正文或重复采纳。
- `rp-veridis-rewrite`绑定source和原稿hash，只有有效complete投影可用于该回复显示；skipped/failed/取消/旧source仍保留原稿。缓存还校验有效设置、narrative与upstream，已执行请求失败后也保留尝试数。它是用户明确授权的可选措辞显示层，不是第三正文模式或格式补交。
- 管理要求严格当前来源与异步激活租约；后台合法祖先恢复另有守卫。私有结果用开始revisionCAS，状态/配置变更不能让旧模型结果覆盖新写入。界面刷新读取真实收据，不把下载、启用或格式原样视为生态采纳/语义审阅成功。

两类来源默认关闭且autoUpdate默认关闭；原文件固定commit/hash，不打补丁、不复制核心提示词/算法。下载候选不等于兼容验收，暂存激活仍检查合成兼容、空闲、管理租约/CAS及坏commit历史，symlink/越界拒绝。管理保留未知JSON与私有Key，含Key数组只按唯一id合并或拒绝不确定重排。功能与支持范围见 `NPC-PARALLEL.md`、`VERIDIS-REWRITE.md`，测试命令见 `../TESTING.md`；原字节和结构保持不证明全酒馆能力或语义完全等价。

### NPC技术校验与旧错误收据恢复

NPC生成/接入由独立受管岗位完成；仅在对应来源的原候选与生态报告通过校验时采纳。真实业务reject可整批隔离，但用户承诺没有匹配本拍真实用户／已保存正文锚点属于技术校验失败，不允许把旧生态推进一拍后标complete。针对同一报告最多收费修复一次，仍失败则pending，下一输入前必须恢复。

旧版精确“无来源承诺隔离＋complete”收据自动视为需恢复；恢复使用该正文前生态为基准，保留已完成账本/世界/原交付，不因已有错误来源快照就跳过校验。有效恢复只推进同一拍到原应有round，失败的修复不会清掉该门禁。明确通过的新收据或已完成的修复标记消除旧错误；旧收据与原稿保持append-only。这是已持久化数据的读取/恢复兼容，不是恢复旧正文生成机制。

## 显示作用域与验收

完整脚手架/`rule_check` 与正文是独立正则作用域。检查只接受自己的完整覆盖规则一次，捕获文本转义进入原HTML，不继续把内联对白规则跑进其字面示例，不产生嵌套整页文档。无renderer的检查进入思维折叠，不当正文；普通正文/BBS规则不受此例外影响。

已隔离片段还原按父到子、索引降序，不能删除占位符来掩盖正文丢失。严格 `<options>` 在显示策略层保留，到React才转按钮；原稿、事实、上下文和旧存档不回写。显示验收必须在桌面/手机实际展开与收起，逐字核对标签示例、完整报告、围栏及源码尾巴，不能只看折叠壳和pageErrors。

## 维护检查

修改引擎须说明为何仍满足单作者、固定3/2/2、原稿先行、冻结事实输入、串行落树与恢复不重复。合成回归至少覆盖两模式、慢后台、排队、半稿、取消、切支、重Roll和缺失收据；原插件、真实模型和生产只读核对另行授权、独立报告，不用重生成故事凑测试成功。
