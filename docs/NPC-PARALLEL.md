# 众生侧写：原 NPC Parallel 融入鲜活世界

原插件提供场外经历候选，鲜活世界统一校验与采纳。安装、启用、候选生成和生态采纳是不同状态；本文不声明某台实例的部署状态或完整酒馆兼容。

## 定位与事实边界

固定上游为 [ug776732-arch/npc-parallel](https://github.com/ug776732-arch/npc-parallel)。原插件负责 NPC 场外经历候选；梨园的鲜活世界负责统一对齐、认知／事件校验、采纳与提交。它不是第二位正文作者，也不作为普通拍后插件再重复推进一遍人物。

- `rpNarrative`、`rpAuthorDraft` 与原绑定交付不追加侧写、不被原插件改写。
- 原插件在隔离的虚拟聊天中运行；对消息的追加只发生于副本，宿主提取结构化候选并保存为私有派生数据。
- 候选文本与“知道／不知道”等描述不能自行变成事实。通过统一生态采纳的状态可以影响后续世界；原始候选不能绕过生态提交直接进入作者正文、MVU 或数据库。
- 阅读场外侧写不代表用户角色已经知情；知情变化仍要符合来源与传播约束。程序和提示词门禁不构成对所有文本的形式化认知隔离证明。

## 一拍中的位置

```text
同一个 direct/director 主作者完成正文与原格式
→ 保存事实、完整原稿和原交付；onAuthorReady 立即展示
→ 鲜活世界这一后台分支：
   原 NPC Parallel 生成场外候选
   → 鲜活世界统一接入、验证与采纳
   → 引擎在来源／取消／分支守卫通过后提交生态与侧写收据
```

鲜活世界仍与场记、世界、数据库、酒馆助手／模板／MVU及 Veridis 显示润色并发。NPC 位于生态分支内部，不增加第七条独立故事推进链；世界、数据库与 MVU 不默认等待侧写。

存在侧写候选时，生态接入模型处理同一批候选及共享状态，不另写一套同人物经历。原插件关闭或没有产生候选时，沿用相应的原生态路径。原插件失败不会为了显示“成功”再启动独立侧写替代作者。

## 采纳、隔离与恢复

`src/stage/npc-parallel.ts` 对候选绑定 session、card、正文来源、上游 commit、稳定人物 ID 和文本哈希；`npc-ecology.ts` 组织原生成与统一生态接入。

采纳须有完整且唯一的候选决策、正确 actor ID、来自原候选的引用，以及存在于拟提交生态的事件引用；之后仍执行生态转移、认知、用户承诺来源等校验。

- **accepted**：整批通过，可提交相应生态变化。
- **rejected**：明确业务冲突导致整批隔离；不能只留下看似通过的兄弟状态并把整段侧写标成已确认经历。缺少真实承诺来源不是合法业务拒绝。
- **empty**：无侧写候选，不假造人物经历。
- **failed**：生成／解析／校验失败，保留原生态并记录失败或 pending；不宣称已采纳。

决策 schema 修复使用同一明确配置的侧写岗位并计入额度，不改用主演或通用恢复模型。`rp-npc-parallel` 保存来源绑定的收据。历史接续只使用当前祖先链中已采纳且来源匹配的侧写；未采纳原输出不能冒充既成历史。pending 恢复复用可用的来源绑定候选，不重写正文，也不重复采纳已完成状态。

## 使用与原管理页

主界面“酒馆插件”中有独立的“众生侧写”来源／更新卡片及原设置入口。操作顺序：

1. 显式启用鲜活世界，并配置独立 `stepModels.npcParallel` 岗位。
2. 安装或激活已暂存的原版候选；安装通过不自动打开插件执行。
3. 显式启用插件，在原管理页配置 NPC、世界书与模板。
4. 核对原设置自身的 enabled／自动触发开关；外层开关打开不覆盖内层关闭。
5. 后台结束后按正文来源读取 accepted／rejected／failed 收据，不把下载成功或原设置页加载成功当作剧情采纳成功。

原管理页由梨园的酒馆能力适配承载，不是完整酒馆服务器。当前宿主不开放从原管理页直接生成、编辑或删除已采纳历史；历史变更应通过梨园分支／来源操作，不允许原按钮旁路重写故事。世界书材料跟随已启用资料与当前分支，不复制挂载或复活关闭条目。

## 模型、额度与取消

使用独立 `stepModels.npcParallel` 岗位，可按配置绑定 Gemini 3.8 Flash 等受管连接。缺少岗位或岗位不可用时明确失败；不静默换成主演、Luna 或通用恢复模型。模型路由、token 上限及允许的 temperature 由受管通道执行，插件 Key 和自定义端点不外发到模型请求。

原生成、生态接入及 schema 修复共用每 session／card／source **8 次持久请求额度**，与助手／模板／MVU、Veridis 和作者预算分开。重启不重置，失败尝试不退款；请求次数不等于 token 用量，精确用量以 provider 回执为准。取消、切会话／卡／分支、迟到结果和私有状态写入保留来源／revision／CAS 检查。

## 原字节、更新与回退

- 独立来源管理器 `server/npc-parallel-source.ts` 固定唯一公开仓库，不扩展 helper/template 的安装枚举，不接收任意 HTTP 仓库选择。
- 缓存为私有 `.liyuan-npc-parallel/`，POSIX 目录／文件权限为 0700／0600，拒绝 symlink、越界路径与非普通资源；固定完整 commit，复核 Git blob、逐文件及整体 SHA-256。
- 原 JS／CSS／manifest／LICENSE 与受控运行资产保留原始字节，不打补丁、不重编；宿主适配与分支设置独立保存。
- 检查只暂存候选。激活仍需新的合成宿主验收、原字节复核、空闲／管理租约检查与原子 CAS；`activateStaged` 不重新下载也不绕过门禁。
- 新来源与自动更新默认关闭。显式打开自动更新后，主服务按六小时检查固定上游；候选失败保留旧版。保留上一版回退，并永久保留已回退 commit 的屏蔽历史，不能接受新版后自动跳回旧坏 commit。
- 未知普通 manifest 元数据保留；递归拒绝危险原型键，执行／资产字段仍严格校验。新增未支持 API 由合成运行门禁拒绝，不通过修改原源码伪装兼容。

CLI 只暂存，不激活或启用：

```bash
node scripts/install-npc-parallel.mjs --cwd /path/to/liyuan --commit <完整40位commit>
# 运维如需代理可追加 --proxy <无凭据HTTP或HTTPS代理地址>
```

运行服务的 Git 路由由 `server/plugin-git-network.ts` 管理：明确调用参数 → 插件专属环境变量 → 本插件私有 `network.json` → `LIYUAN_TAVERN_GIT_PROXY` → 旧共享 tavern `network.json` → Git HTTP(S) 环境代理回退。NPC 专属变量为 `LIYUAN_NPC_PARALLEL_GIT_PROXY`；Veridis 优先 `LIYUAN_VERIDIS_REWRITE_GIT_PROXY`，兼容旧 `LIYUAN_VERIDIS_GIT_PROXY`。

本插件 `gitProxy: ""` 表示**显式直连**，不会落回共享／环境代理；字段缺省才回退。专属文件位于各自私有目录，POSIX 目录 0700／文件 0600，拒绝 symlink、非法类型、非 HTTP(S) 或含凭据代理。该路由不修改 helper/template 共享设置或聊天模型连接，不硬编码实例网关。

## 验证与限制

专项命令见 [TESTING](../TESTING.md)。原版浏览器验收需显式原资产 fixture；没有 fixture 的 skip 不能计成原版运行通过。原字节校验、合成采纳/分支测试、原管理页与真实模型请求各有独立覆盖范围，不证明所有社区卡、全部上游 API、未来更新或信息传播语义正确。

安装器的固定来源基线为 v1.1.0、commit `8e097d5819ce3928a2ead3d8cf7537d969524bb3`，文件集 SHA-256 `8a5c8e711e9a39fe66f8ecbd91027754cbef3787b0279d244ffd7c08059bd842`。这是可复核来源，不是当前上游最新版本或每台实例已安装状态。上游原文件与私有故事/状态不进入公开发行包；使用和复用遵循原 LICENSE，不以梨园许可替代。

## 诊断与技术恢复

- 在场判定也可能消耗推理输出预算。`npcManagedOutputBudget` 为受管请求保留至少 4096 输出预算，仍受 32000 上限、来源守卫和八次额度约束；截断不能被采纳，失败返回脱敏分类。
- 原设置显示实际独立受管 provider/model；旧自定义 API 配置保留但不参与传输、不复制 Key。改变作者模型不会改变 `npcParallel`，应到连接/岗位设置修改。
- 技术来源校验失败，例如缺少本拍真实锚点的 `userCommitment`，最多在同来源、同岗位上收费修复一次，仍失败保留 pending。不能拿候选或旧生态快照把本拍记成 complete。
- 旧精确“无来源承诺隔离却 complete”收据按正文前生态恢复并标记校正，不把错误快照视为成功，不增加第二个生态 round；账本、世界和原交付不重复运行。
- 原管理页采用完整画布、原分类和控件，主题、手机分类及滚动由宿主适配。页面加载成功不证明内层自动触发已启用；先核对两层开关和来源收据。

源码地图：`server/npc-parallel-{source,runtime,http}.ts` 管理原资产、浏览器执行与 API；`server/plugin-git-network.ts` 管理 Git 路由；`src/stage/npc-parallel.ts` 校验候选/收据；`src/stage/npc-ecology.ts` 接入统一生态；`src/stage/engine.ts` 负责并发计算后的守卫、串行提交与恢复。
