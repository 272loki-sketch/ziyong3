# 当前鲜活世界生态

生态提供镜头外生活和自然候选，不是第二正文或新的事实权威。

## 三层

1. 全局叙事原型池：可复用生活/场所/事件机制。
2. 卡级生态池：依据原始人物/作品/地区资料生成的适配候选。
3. 分支生态运行态：本分支人物生活、场所、事件、通讯、认知与传播状态。

## 双模式

直出读取已有池和生态的只读投影，不新生成拍前arrival；导演模式的生态专家也读取真实已有资料。后台搜索/双池备料为后续拍服务，不把待生成候选当当前事实。

后台备料分running/ready，单条运行链、串行写入，写前重读最新池并合并useCount。ready才消费，不等待未完成的背景池阻塞正文首字。

## 拍后与认知

保存正文后的after-math依据宿主绑定的sourceRefs/原文片段处理人物、事件、场所和信息传播；候选、未保存草稿、专家建议不能成为committed依据。家庭/势力/地域认知边界和传播链要校验，不把全知后台信息给角色。

世界转移与生态可并行计算，但按既定顺序落树；取消/切支拒绝迟到结果。失败保留真实状态并有明确降级，而不是伪造完整生态。

启用/搜索和模型插头是独立设置，不因模式或Luna改名改变Flash岗位。入口 `src/stage/literary-ecology.ts`、`passive-ecology.ts`；测试 `literary-ecology.test.ts`、`ecology-narrative-commitment.test.ts`。


## 原众生侧写作为统一候选来源

原 NPC Parallel 接入现有生态，**不是与鲜活世界独立推进的人物世界引擎**。原稿先交付；场外经历由原插件在冻结正文、拍前生态/账本和原启用资料上生成，候选绑定 session/card/source、人物稳定 id、原文本 hash 与 upstream commit，再由鲜活世界统一接入/转移校验，最后由引擎串行提交状态和 `rp-npc-parallel` 收据。

有候选时，同一条生态计算链处理候选及共享状态；没有启用或没有候选时保留相应原生态路径。缺schema可在同一个独立`npcParallel`岗位有界修复并计入额度，不借用主演或再让另一个生态作者各写一套人物经历。原插件失败明确pending/降级，不能通过旁路侧写伪装成功。

采纳要求完整唯一裁决、actor 身份、原候选引用及有效事件引用，之后仍验认知/传播与用户承诺来源。明确业务拒绝会丢弃整批拟议状态、保留原生态；无真实来源的用户承诺属于技术失败，同来源同岗位最多收费修复一次，仍失败留 pending，不能冒充合法 reject/complete。未采纳文本不能以已发生经历进入下拍历史。原稿和 Session Tree 正文不追加侧写，读者知道幕后不等于用户角色知情。

accepted收据和统一生态状态是该场外候选的权威落点；原raw侧写不绕过采纳直接投喂作者、MVU、数据库或记忆。pending恢复只复用当前合法来源候选/完成收据，不重生成正文或重复推进。六路后台中的Veridis是独立显示润色，不为生态提供事实输入。

启用需用户显式打开鲜活世界、原侧写插件并配置可用独立岗位；关闭原设置/资料不能被宿主复活。固定原版私有缓存、原管理页支持面、额度、更新门禁和局限见 [NPC-PARALLEL](NPC-PARALLEL.md)。这些程序校验不构成所有文本认知/传播正确的形式化证明。
